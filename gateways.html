Gateways: Build & Compare Challenge

Easy: Exclusive (XOR) Split

Model a process that starts with "Verify Purchase Order Status". After this, a decision is needed: "Supplier Confirmation Received?". If YES, the process must "Generate Goods Receipt". If NO, the process must "Send Reminder Email". Both paths then merge and lead to "Update ERP System".

Elements Needed:
  • 1x Start Event
  • 4x Tasks
  • 1x Exclusive (XOR) Gateway (for the split)
  • 1x Exclusive (XOR) Gateway (for the merge)
  • Label the 'yes' and 'no' paths!

❌ Mistake 1: Missing Gateway Labels

This is the most critical error. An Exclusive (XOR) or Inclusive (OR) gateway is a *question*. The outgoing paths are the *answers*. If you don't add a question to the gateway (e.g., "Supplier Confirmed?") and labels to the paths (e.g., "yes" / "no"), the diagram is broken and unreadable.

🔴 BAD

Imagine this diagram *without* the "Data Available?", "yes", and "no" labels. It would be impossible to understand the logic.

🟢 GOOD

This is perfect. The gateway asks a clear question, and the paths provide clear "yes" / "no" answers.

❌ Mistake 2: Using the Wrong Gateway (AND vs. XOR)

Using the wrong gateway type breaks the process logic. Don't use a Parallel (AND `+`) gateway if you mean to make an exclusive choice. Don't use an Exclusive (XOR `X`) gateway if you want tasks to run in parallel.

🟢 GOOD

This is correct for parallel work. The AND `+` gateway *splits* the flow, forcing "Perform Quality Inspection" AND "Packaging & Labeling" to *both* run.

❌ Mistake 3: Unbalanced Gateways

A critical rule: **You must merge paths with the same gateway type you used to split them.** If you split with an AND `+` gateway, you MUST merge with an AND `+` gateway. If you split with XOR `X`, you merge with XOR `X`. Mixing them (e.g., splitting with AND, merging with XOR) can cause deadlocks or unwanted duplicate process flows.

🔴 BAD

It is a *major error* if the second `X` gateway (the merge) was an `+` gateway instead. The process would stop there and wont move ahead.

🟢 GOOD

This is a perfectly balanced process. The flow splits with an XOR `X` gateway and merges with another XOR `X` gateway.

❌ Mistake 4: Confusing Inclusive (OR) and Exclusive (XOR)

`XOR (X)` means: **One, and only one, path is possible.** (e.g., "yes" or "no"). `OR (O)` means: **One *or more* paths are possible.** (e.g., "Notify Transport" and/or "Notify Warehouse"). Using XOR when multiple paths might be valid is a logic error.

🔴 BAD

It would be wrong to use an XOR `X` gateway here. That would mean if an order was *both* "Urgent" and "Large Volume," the process could only pick *one* path, which is bad.

🟢 GOOD

This is correct. The OR `O` gateway allows the process to send *just one* notification, or *both*, depending on the conditions. This is flexible.

❌ Mistake 5: Merging Paths Directly Into a Task

A Task is not a Gateway! You cannot have two (or more) sequence flows going *into* a single task. This is a modeling error. You *must* use a gateway to merge the paths *before* the flow continues to the next task.

🔴 BAD

Both Tasks Should Not Join Directly to a Task, A logic Should be Implemented with gateways

🟢 GOOD

This is correct. The Two Tasks Uses Here XOR gateway which means it waits for any one branch to be finished and move forward.
